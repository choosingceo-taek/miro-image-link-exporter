# 내 PC 로 매일 자동 수집하기 — GitHub 러너 설치 안내

이 안내를 따라 하면, 막혀 있던 브랜드(H&M 상품 페이지·Lululemon·Sezane·Anthropologie·WHBM 등 약 30개)를
**owner 의 PC 가 매일 아침 스스로** 모읍니다. 버튼을 누를 사람이 필요 없습니다.

- 지금: 크롬 확장이 밤 23:00 에 돕니다. PC 가 켜져 있고 크롬이 열려 있어야 합니다. 11/26 밤에는 이게 안 돼서 19개 브랜드가 하루 묵었습니다.
- 이 안내 뒤: GitHub 이 평일 아침 08:30(한국 시간)에 **내 PC 에 일을 보냅니다**. PC 에 설치한 작은 프로그램(이하 "러너")이 그 일을 받아,
  PC 에 깔린 진짜 크롬으로 사이트를 엽니다. 확장과 같은 PC·같은 인터넷(IP)이라 사이트가 똑같이 열립니다.
- PC 가 꺼져 있었다면: 일이 줄에서 기다립니다. **켜지면 그때 돕니다**(GitHub 은 최대 24시간 기다립니다).
- 수집하는 동안 크롬·파이어폭스 창이 몇 번 떴다 닫힙니다(보통 30분~2시간). 그 창은 건드리지 않아도 됩니다.
- 위장·우회 프로그램, 유료 서비스는 쓰지 않습니다. 진짜 브라우저가 자기 모습 그대로 사이트에 갑니다.
  집·회사 인터넷의 진짜 브라우저로도 막히는 사이트는 억지로 뚫지 않고 리포트에 "막힘"으로 적은 뒤 그 브랜드는 쉽니다(확장 담당으로 남음).

무엇을 하는지는 [`scripts/pc-collect.mjs`](../scripts/pc-collect.mjs) 맨 위, 브랜드별로 어떤 브라우저를 쓰는지는
[`scripts/pc-plan.mjs`](../scripts/pc-plan.mjs) 맨 위에 있습니다.

| 순서 | 할 일 | 시간 |
|---|---|---|
| 1 | 먼저 확인할 것(공개 저장소 설정 · 회사 규정 · 크롬·Git 설치) | 10분 |
| 2 | 러너 내려받기·등록(윈도우 또는 맥) | 10~15분 |

| | **합계** | **약 45분** |

## 1. 먼저 확인할 것

### 1-1. 공개 저장소 주의 (꼭)

이 저장소는 **공개(public)** 입니다. 공개 저장소에 내 PC 러너를 달면, 모르는 사람이 보낸 변경 요청(Pull Request)의 코드가
내 PC 에서 돌 수 있습니다. 아래 설정 하나로 막습니다 — **러너를 설치하기 전에** 하세요.

1. 저장소 페이지 위쪽 메뉴에서 **Settings**(톱니바퀴)를 누릅니다.
2. 왼쪽 메뉴에서 **Actions → General** 을 누릅니다.
3. 아래로 내려 **"Fork pull request workflows from outside collaborators"** 칸을 찾습니다.
4. **"Require approval for all external contributors"**(모든 외부 기여자 승인 필요)를 고르고 **Save** 를 누릅니다.

> [화면 설명] 라디오 버튼 세 개가 세로로 있습니다. 맨 아래가 "Require approval for all external contributors" 입니다.

그 뒤로는 모르는 사람의 Pull Request 에 **"Approve and run"** 버튼이 생깁니다. 누가 보냈는지 모르면 누르지 마세요.
가장 안전한 방법은 저장소를 비공개(private)로 바꾸는 것입니다 — 다른 사람이 이 저장소를 볼 필요가 없다면 고려하세요(owner 판단).

### 1-2. 회사 PC 라면 — 회사 규정

회사 PC 에 개인 GitHub 의 러너를 설치해도 되는지 회사 규정을 먼저 확인하세요. 러너는 회사 밖(GitHub)과 통신하고,
수집 결과(상품 이름·가격 등 공개된 쇼핑몰 정보)를 이 저장소에 올립니다. PC 안의 문서·계정 정보는 올리지 않습니다.
리포트에는 운영체제 종류(windows/mac)만 적고 PC 이름·사용자 이름은 적지 않습니다(오류 글 속의 내 폴더 경로도 `~` 로 지웁니다).

공개 저장소라 **실행 기록(Actions 로그)은 누구나 볼 수 있습니다.** 로그에는 러너 이름과 러너를 설치한 폴더 경로가 찍힙니다.
그래서 러너 이름은 PC 이름 대신 `rack-pc-1` 같은 이름으로 짓고(2-3), 맥은 사용자 이름이 경로에 들어가지 않게
`/Users/Shared` 아래에 설치합니다(3-2).
회사 IT 가 막을 수 있는 것과 확인하는 법은 [5절](#5-회사-it-정책이-막을-수-있는-것과-확인하는-법)에 있습니다.

### 1-3. 크롬과 Git 이 깔려 있나

- **구글 크롬**: 크롬 주소창에 `chrome://version` 을 쳐서 버전이 보이면 됩니다. 러너는 이 크롬을 씁니다(따로 받지 않습니다).
- **Git**(결과를 저장소에 올리는 프로그램):
  - 윈도우: 시작 → "PowerShell" 을 열고 `git --version` 을 칩니다. "git version 2.…" 이 나오면 됩니다.
    안 나오면 <https://git-scm.com/download/win> 에서 받아 설치합니다(물음에는 모두 기본값 그대로 Next).
  - 맥: 터미널에서 `git --version` 을 칩니다. 설치하라는 창이 뜨면 **설치** 를 누릅니다(몇 분).
- 파이어폭스는 깔 필요가 없습니다. 첫 실행 때 러너가 자동화용 파이어폭스를 스스로 받습니다(한 번만, 약 80MB).

## 2. 러너 설치 — 윈도우

> 맥이면 [3절](#3-러너-설치--맥)로 가세요.

### 2-1. 등록 화면 열기

1. 저장소 페이지 → **Settings** → 왼쪽 메뉴 **Actions → Runners** 를 누릅니다.
2. 오른쪽 위 초록 버튼 **New self-hosted runner** 를 누릅니다.
3. **Runner image** 에서 **Windows** 를, **Architecture** 에서 **x64** 를 고릅니다.

> [화면 설명] 아래쪽에 회색 상자 두 개가 나옵니다 — 위가 **Download**, 아래가 **Configure** 입니다. 상자마다 오른쪽에 복사 버튼이 있습니다.
> Configure 상자 안의 `--token` 뒤 글자가 **등록 토큰**입니다. 이 화면에서만 보이고 약 1시간 뒤 쓸 수 없게 됩니다.
> **토큰을 메신저·메일·문서에 옮기지 마세요.** 이 화면에서 PowerShell 로 바로 복사해 붙이기만 합니다.

### 2-2. 내려받기

1. 시작 메뉴에서 "PowerShell" 을 찾아 **마우스 오른쪽 → 관리자 권한으로 실행** 합니다(3절의 '서비스' 방식에 필요합니다. 관리자 권한이 없으면 그냥 실행해도 되고, 3-B 방식을 씁니다).
2. 아래를 칩니다(경로에 한글·공백이 없는 곳이 좋습니다).
   ```
   mkdir C:\actions-runner
   cd C:\actions-runner
   ```
3. GitHub 화면 **Download** 상자의 줄(`Invoke-WebRequest …` 와 `Add-Type … ExtractToDirectory …`)을 **한 줄씩** 복사해 붙이고 Enter 를 누릅니다.
   (중간의 `# Optional: Validate the hash` 줄은 건너뛰어도 됩니다.)

### 2-3. 등록(이름표 `rack-pc` 붙이기)

1. GitHub 화면 **Configure** 상자의 첫 줄(`./config.cmd --url https://github.com/… --token …`)을 복사해 PowerShell 에 붙이고 Enter.
2. 물음이 차례로 나옵니다.

   | 물음 | 답 |
   |---|---|
   | Enter the name of the runner group | 그냥 Enter |
   | Enter the name of runner | `rack-pc-1` 처럼 아무 이름(기본값은 PC 이름 — 공개 저장소라 PC 이름을 보이고 싶지 않으면 바꾸세요) |
   | **Enter any additional labels** | **`rack-pc`** ← 꼭 이대로. 워크플로가 이 이름표가 붙은 러너만 부릅니다 |
   | Enter name of work folder | 그냥 Enter |
   | Would you like to run the runner as service? | 다음 3절을 읽고 고릅니다(서비스면 `Y`, 아니면 `N`) |

3. 마지막에 "Settings Saved." 가 나오면 등록 끝입니다.

### 2-4. 재부팅해도 켜지게 — 둘 중 하나

**A. 서비스로 (등록할 때 `Y`)** — PC 가 켜지기만 하면 로그인 전에도 돕니다.
- "User account to use for the service" 물음은 그냥 Enter(기본 계정 NETWORK SERVICE — 권한이 낮아 안전합니다).
- 단점: 윈도우 서비스에는 화면이 없어서 **크롬이 창 없이** 돕니다. 사이트가 '창 없는 크롬'을 더 쉽게 알아보고 막을 수 있습니다.
  리포트에 "창 없이"라고 적힙니다. 막히는 브랜드가 많으면 B 로 바꾸세요.

**B. 로그인할 때 자동 시작 (등록할 때 `N`) — 권장(창을 띄운 진짜 크롬)**
1. 시작 → "작업 스케줄러" 를 엽니다.
2. 오른쪽 **작업 만들기…** 를 누릅니다(‘기본 작업 만들기’ 아님).
3. **일반** 탭: 이름 `GitHub runner (rack-pc)` · **사용자가 로그온할 때만 실행** 선택.
4. **트리거** 탭: **새로 만들기** → 작업 시작 **로그온할 때** → 확인.
5. **동작** 탭: **새로 만들기** → 프로그램/스크립트 `C:\actions-runner\run.cmd` · 시작 위치 `C:\actions-runner` → 확인.
6. **조건** 탭: 노트북이면 **"컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작"** 체크를 뺍니다.
7. **설정** 탭: **"다음 시간 이상 작업이 실행되면 중지"** 체크를 뺍니다 · "작업이 이미 실행 중이면" → **새 인스턴스를 시작하지 않음**.
8. 확인 → 목록에서 이 작업을 **마우스 오른쪽 → 실행**. 검은 창이 하나 뜨고 "Listening for Jobs" 가 보이면 됩니다(그 창은 최소화해 두고 닫지 마세요).

- 화면을 잠가도(Win+L) 돕니다. **로그아웃하면 멈춥니다**(다음 로그인 때 다시 켜짐).

### 2-5. 확인

저장소 → Settings → Actions → **Runners** 에 방금 이름이 보이고, 옆에 초록 점과 **Idle** 이 보이면 준비 끝입니다.
이름표 칸에 `self-hosted` · `Windows` · `X64` · **`rack-pc`** 가 있어야 합니다.

## 3. 러너 설치 — 맥

### 3-1. 등록 화면 열기

1. 저장소 → **Settings** → **Actions → Runners** → **New self-hosted runner**.
2. **Runner image** 에서 **macOS** 를 고릅니다. **Architecture** 는 메뉴 막대의 사과 → **이 Mac에 관하여** 에서
   칩이 "Apple M…" 이면 **ARM64**, "Intel" 이면 **x64**.

> [화면 설명] 윈도우와 같이 **Download**·**Configure** 상자가 나옵니다. Configure 상자의 `--token` 뒤 글자는 이 화면에서만 쓰고 옮기지 마세요.

### 3-2. 내려받기·등록

1. 응용 프로그램 → 유틸리티 → **터미널** 을 엽니다.
2. 먼저 `cd /Users/Shared` 를 칩니다(로그에 사용자 이름이 안 찍히게 — 1-2).
3. **Download** 상자의 줄(`mkdir actions-runner && cd actions-runner` · `curl -o …` · `tar xzf …`)을 한 줄씩 붙이고 Enter.
4. **Configure** 상자의 첫 줄(`./config.sh --url … --token …`)을 붙이고 Enter. 물음 답은 윈도우 표와 같습니다 —
   **additional labels 에 `rack-pc`**. (서비스 물음은 맥에서는 나오지 않습니다.)

### 3-3. 재부팅해도 켜지게 (서비스)

같은 터미널에서:
```
./svc.sh install
./svc.sh start
./svc.sh status
```
`status` 에 "Started" 가 보이면 됩니다. 맥의 서비스는 **로그인한 사용자 화면에서** 돌기 때문에 크롬 창을 띄울 수 있습니다.
재부팅 뒤에는 **로그인하면** 자동으로 다시 켜집니다(로그인 전에는 안 돕니다).
처음 크롬이 뜰 때 "터미널(또는 Runner.Listener)이 … 하려고 합니다" 같은 창이 뜨면 **허용** 을 누릅니다.

### 3-4. 확인

윈도우 2-5 와 같습니다 — Runners 목록에 초록 점·**Idle**·이름표 **`rack-pc`**.

## 4. 전원·절전

러너는 PC 가 **잠들어 있으면 일을 못 받습니다**. 화면이 꺼지거나 잠기는 것은 괜찮습니다.

**윈도우**
1. 설정 → 시스템 → **전원 및 배터리**(윈도우 10: 전원 및 절전) → **화면 및 절전**.
2. "전원에 연결된 경우 … 후 장치를 절전 상태로 전환" → **안 함**(또는 최소한 수집이 끝날 오전 11시까지 깨어 있게 충분히 길게).
3. 노트북이면: 제어판 → 전원 옵션 → **덮개를 닫으면 수행할 작업** → 전원 연결 시 **아무 것도 안 함**.

**맥**
1. 시스템 설정 → **배터리**(데스크톱은 **에너지**) → 옵션.
2. **"전원 어댑터 사용 시 디스플레이가 꺼져 있을 때 자동으로 잠자기 방지"** 를 켭니다.
3. 노트북은 덮개를 닫으면 잠듭니다(외부 모니터가 없으면) — 수집 시간엔 열어 두세요.
4. (선택) 매일 08:20 에 깨우기: 터미널에서 `sudo pmset repeat wakeorpoweron MTWRF 08:20:00`(맥 암호를 물으면 입력). 끄려면 `sudo pmset repeat cancel`.

## 5. 회사 IT 정책이 막을 수 있는 것과 확인하는 법

| 막힐 수 있는 것 | 어떻게 보이나 | 확인·대처 |
|---|---|---|
| 프로그램 실행 제한(허용 목록·관리자 권한 없음) | `config.cmd` 가 "이 앱은 차단되었습니다"·"액세스 거부" | IT 에 `C:\actions-runner` 폴더 실행 허용을 요청. 관리자 권한만 없으면 2-4 의 **B** 방식(서비스 등록 안 함) |
| 서비스 등록 금지 | 등록 끝에 서비스 오류 | **B** 방식으로 |
| 회사 방화벽·프록시 | Runners 목록에서 러너가 회색(Offline) · 설치 중 다운로드 실패 | 브라우저로 `https://github.com` · `https://registry.npmjs.org/playwright` · `https://market-research-uzs2.onrender.com/blocked-brands.json` 가 열리는지 봅니다. 회사가 프록시를 쓰면 `C:\actions-runner\.env`(맥은 `/Users/Shared/actions-runner/.env`) 파일에 `https_proxy=http://프록시주소:포트` 한 줄을 넣고 러너를 다시 켭니다(주소는 IT 에 문의) |
| 파이어폭스 다운로드 차단 | 리포트에 "파이어폭스 없음" | 괜찮습니다 — 그 브랜드는 크롬으로 돕니다. 필요하면 IT 에 `playwright.azureedge.net` 등 허용 요청 |
| 보안 프로그램(백신·EDR)이 자동으로 움직이는 크롬을 막음 | 리포트에 "크롬을 못 띄움" · 크롬 창이 뜨자마자 닫힘 | IT 에 `C:\actions-runner` 와 크롬 자동 실행 예외 요청 |
| 쇼핑몰 접속 차단(회사가 쇼핑 사이트를 막음) | 리포트의 브랜드마다 "오류: net::ERR…" | 회사망에서는 어렵습니다 — 집 PC 에 설치하세요 |

**한 번에 확인하는 법** — [6절](#6-시험-실행--처음-한-번)의 "계획만" 실행을 돌리면, 리포트 첫머리에
`브라우저: 크롬 1xx · 파이어폭스 1xx` 와 막힌 것이 적힙니다. 설치·방화벽·보안 프로그램 문제는 대부분 여기서 드러납니다.

---

## 6. 시험 실행 — 처음 한 번

1. 저장소 위쪽 **Actions** 탭 → 왼쪽 목록 **PC collect (my PC, real browser)** → 오른쪽 **Run workflow**.
2. **계획만**: `steps` 칸에 `plan`, `store` 칸에 `0` → 초록 **Run workflow**. 2~5분 뒤 저장소의 `pc-collect-report.md` 를 엽니다.
   - 첫머리에 `브라우저: 크롬 1xx…` 가 보이면 러너·크롬이 준비된 것입니다.
   - "계획 — 브랜드별 엔진과 근거"를 누르면 브랜드마다 크롬/파이어폭스를 고른 이유가 보입니다.
3. **읽기만(저장 안 함)**: `steps` 비움(기본) · `store` `0` · `brands` 에 `WHBM` · `report_tag` 에 `try1` → Run.
   10분쯤 뒤 `pc-collect-try1-<번호>.md` 에서 WHBM 이 몇 개 읽혔는지 봅니다. 저장소 데이터는 바뀌지 않습니다.
4. 됐으면 끝입니다. 다음 평일 08:30 부터 저절로 돕니다.

> `report_tag` 를 줄 때는 **`store` 를 꼭 `0`** 으로 둡니다(아니면 시작하자마자 멈춥니다 — 시험 실행이 진짜 데이터를 바꾸지 않게 막아 둔 것).

## 7. 날마다 무엇을 보나

- 아침 리포트 `browser-collect-report.md` 맨 끝에 **"PC 잡"** 절이 붙습니다.
  - `✅ 오늘 결과` — 정상.
  - `⚠ 오래된 결과` / `⚠ 결과 없음` — PC 가 꺼져 있었거나 러너가 멈췄습니다. Runners 목록에서 초록 점인지 보세요.
- 자세한 것은 `pc-collect-report.md`: 브랜드마다 모은 개수 · 저장 요청 수(쓰기 예산) · 429 로 멈춘 사이트 · "이 PC 의 진짜 브라우저로도 막힌 브랜드".
- 목록이 최근(20시간 안)에 저장된 브랜드는 건너뜁니다 — 확장이 어젯밤 잘 돌았으면 PC 는 상품 페이지(혼용률·컬러)만 채웁니다.
  확장이 빠진 날에만 목록까지 채워, 하루 쓰기 한도(Cloudflare 무료 1,000회)를 아낍니다.

## 8. 시간 바꾸기

[`.github/workflows/pc-collect.yml`](../.github/workflows/pc-collect.yml) 의 `cron:` **한 줄**만 고칩니다. GitHub 은 UTC 로 적으므로 한국 시간에서 9시간을 뺍니다.

| 원하는 때(한국) | 적을 값 |
|---|---|
| 평일 08:30 (기본) | `"30 23 * * 0-4"` (UTC 일~목 23:30) |
| 평일 09:30 | `"30 0 * * 1-5"` |
| 평일 12:10(점심) | `"10 3 * * 1-5"` |
| 매일 08:30 | `"30 23 * * *"` |

- 예약 실행은 GitHub 이 붐비면 몇 분~수십 분 늦게 시작될 수 있습니다.
- Cloudflare 의 하루 쓰기 한도는 **09:00 KST** 에 다시 찹니다. 08:30 실행은 그날(UTC) 마지막 몫을 쓰므로, 다른 잡이 한도를 다 썼으면
  남은 몫만 씁니다(리포트에 "쓰기 몫이 … 남음"). 09:00 뒤로 옮기면 새 몫의 앞쪽을 씁니다.
- 창이 떠서 일에 방해되면 점심시간이나 퇴근 무렵으로 옮기세요. 창 없이 돌리려면 저장소 Settings → Secrets and variables → Actions →
  **Variables** 에 `PC_HEADED` = `0` (창 없는 크롬은 더 잘 막힙니다).

## 9. 멈추기·지우기

**잠깐 멈추기(PC 는 그대로)**: Actions 탭 → PC collect → 오른쪽 위 **⋯** → **Disable workflow**. 다시 켤 때 **Enable workflow**.

**러너 끄기**
- 윈도우 A(서비스): 시작 → "서비스" → 목록에서 **GitHub Actions Runner (…)** → **중지**. 다시 켤 때 **시작**.
- 윈도우 B(작업 스케줄러): 러너 검은 창을 닫고, 작업 스케줄러에서 그 작업 → **사용 안 함**.
- 맥: 터미널에서 `cd /Users/Shared/actions-runner` → `./svc.sh stop`.

**완전히 지우기(remove)**
1. 저장소 → Settings → Actions → Runners → 러너 이름 → 오른쪽 **Remove** → 지우는 명령과 **지우기 토큰**이 뜹니다(이것도 옮기지 말고 그 자리에서만).
2. 윈도우: PowerShell(서비스 방식이면 관리자 권한) → `cd C:\actions-runner` → 화면의 `./config.cmd remove --token …` 를 붙여넣기(서비스도 함께 지워집니다).
   B 방식이었으면 작업 스케줄러의 작업도 **삭제**.
3. 맥: `cd /Users/Shared/actions-runner` → `./svc.sh stop` → `./svc.sh uninstall` → 화면의 `./config.sh remove --token …` 를 붙여넣기.
4. `actions-runner` 폴더를 지웁니다.

크롬 확장은 지우지 않아도 됩니다 — 예비로 둡니다. 둘 다 돌아도 PC 는 최근 저장된 목록을 건너뛰어 같은 저장을 두 번 하지 않습니다.

## 10. 문제가 생기면

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| Actions 실행이 "Waiting for a runner to pick up this job…" 에서 멈춤 | PC 가 꺼졌거나 러너가 안 켜짐 | PC 를 켜고 Runners 목록의 초록 점 확인. 24시간 안에 켜지면 그대로 이어서 돕니다 |
| 리포트 "창 없이" | 서비스 방식(윈도우 A) 또는 화면 없음 | 막히는 브랜드가 많으면 윈도우 B 방식으로 |
| 리포트 "크롬을 못 띄움" | 크롬이 없거나 보안 프로그램이 막음 | `chrome://version` 확인 · 5절 |
| 리포트 "429 로 멈춘 사이트" | 그 사이트가 "요청이 많다"고 함 | 그날은 그 사이트를 더 묻지 않습니다. 내일 다시 |
| "이 PC 의 진짜 브라우저로도 막힌 브랜드" | 크롬·파이어폭스 모두 두 번 연달아 막힘 | 14일 쉬었다가 한 번 다시 봅니다. 그동안 확장 담당. 억지로 뚫지 않습니다 |
| "쓰기 예산 부족 — 오늘 건너뜀" | 하루 쓰기 한도를 아끼는 중 | 다음 날 앞쪽에서 돕니다. 예산은 Variables 의 `PC_WRITE_BUDGET`(기본 120) |

브랜드를 사람이 직접 정하고 싶으면(예: 이 브랜드는 늘 파이어폭스 · 이 브랜드는 PC 에서 멈춤) 저장소의 [`pc-brands.json`](../pc-brands.json) 의 `overrides` 에 적습니다.
